01 Design philosophy

Quality comes from traceable evidence and active falsification — not from more agents. Seven rules keep every run honest.

  1. 01

    Discipline over orchestration

    Quality comes from traceable evidence and active falsification, not from more agents.

  2. 02

    One skill, zero runtime dependencies

    One portable skill, no framework. The scripts are Python standard library only, and no host-specific tool names are hardcoded.

  3. 03

    Files are the source of truth

    Research artifacts are written to disk; the model context keeps only conclusions.

  4. 04

    Mechanical gates over good intentions

    A validator enforces the evidence rules and can fail the run.

  5. 05

    Two tiers, not three

    quick and normal, chosen automatically from the question. No heavy orchestration.

  6. 06

    Verifiability over polish

    Every claim is clickable; anything unverified is labelled unknown.

  7. 07

    Falsification is mandatory

    Counter-evidence and contradictions are actively searched, never assumed absent.

02 Why another research skill

Most deep-research tooling is either a heavy multi-agent framework or a thin prompt. This skill takes the middle path.

  • Heavy multi-agent frameworks

    Split across many agents

    The work is handed to many specialised agents, with a layer of orchestration holding them together.

  • Thin single prompts

    One prompt, nothing checked

    A single prompt asks a model for a research report. Nothing verifies what comes back.

  • This project · the middle path

    One skill, evidence on disk

    Evidence is written to disk, a validator can fail the run, anything unverified is labelled unknown, and counter-evidence is searched on purpose.

It borrows the best ideas from both open-source and big-tech deep research — evidence contracts, source quality tiers, refute obligations, budget-aware stopping, multi-perspective questioning — and distils them into a single, self-contained skill.

03 How it works

Twelve stages, two hard gates. Raw retrieval and structured evidence go to disk; the context keeps only conclusions.

  1. 1

    Plan

    5 stages

    Work out what is being asked, what the host can do, and how deep to go.

    1. 01probecapability check
    2. 02anchorlanguage · format · output dir
    3. 03clarify1–3 scope questions
    4. 04tierquick | normal
    5. 05plannamed research axes
  2. 2

    Research

    2 stages

    Search, open the original pages, read them, and merge the evidence into one file.

    1. 06researchsearch → open → evaluate
    2. 07mergeone evidence.json
  3. 08Gate ①validator must report ok
  4. 3

    Verify & write

    3 stages

    Write the report from that evidence, render the citations, and deliver the four artifacts.

    1. 09writeinline citations, no new facts
    2. 10Gate ②no orphan, no unresolved
    3. 11sourcesnormalize + de-duplicate
    4. 12deliver4 artifacts + coverage & gaps

Gate ① runs the evidence validator: the run only continues when it reports ok. Gate ② renders the citations and fails on any orphan or unresolved reference. When a gate cannot pass, the run stops and reports that honestly instead of delivering a broken report.

Key rules

  • Search before fetching. A result snippet is never evidence.
  • Open the original page and read it before admitting anything.
  • Actively search counter-evidence, failed cases and dissenting sources.
  • Label what stays unverifiable as unknown, never a guess.
  • Stop at the budget and return the best coverage found rather than looping forever.

Budget and stop conditions

Tier Max fetches Min distinct sources Max rounds per axis
quick 8 5 3
normal 25 15 3

When the budget is exhausted the run stops, returns the coverage it reached, and lists explicitly what was not covered.

04 Deliverables

Every run writes four artifacts into one directory.

meld-deepresearch-reports/YYYY-MM-DD-{slug}-{hex4}/

  • report.md

    The final report, with inline numbered citations.

  • sources.md

    The de-duplicated source list.

  • evidence.json

    Structured claims, evidence, sources, and boundaries.

  • citations.json

    The citation map used to render the report.

The report's own ## Sources section is written by the renderer, not by the model, and citations are never hand-numbered. If the host has no filesystem access, the report is returned inline and the run states that nothing was persisted.

05 Install

The skill is a directory containing SKILL.md, references/ and scripts/. Install it with either one-liner.

skills.sh / Vercel skills CLI

npx skills add sogeisetsu/meld-deepresearch

Installs into the hosts that the skills CLI supports.

GitHub CLI v2.90.0+

gh skill install sogeisetsu/meld-deepresearch meld-deepresearch

Works across Copilot, Claude Code, Cursor, Codex and Gemini.

Manual install

Copy skills/meld-deepresearch/ into your host's skills directory. The cross-tool path ~/.agents/skills/ is recognized by several hosts. No configuration is required: the skill uses the host's model, and you do not configure a model for it.

  • opencode
  • Claude Code
  • Codex
  • Cursor
  • GitHub Copilot
  • Gemini CLI

Requirements

  • A host that supports the Agent Skills open standard.
  • Network search and fetch capability.
  • File read/write and command execution, for the scripts and the artifacts.
  • Python 3, standard library only, for the validator, the citation renderer and the source de-duplicator. The run degrades gracefully when those scripts cannot be executed, and says so in its output.

01 设计理念

质量来自可追溯的证据和主动证伪，而不是更多的智能体。七条规则让每一次运行都经得起检查。

  1. 01

    纪律优先于编排

    质量来自可追溯的证据和主动证伪，而不是更多的智能体。

  2. 02

    一个 skill，零运行时依赖

    只有一个可移植的 skill，没有框架。脚本只用 Python 标准库，也不硬编码任何宿主专属的工具名。

  3. 03

    文件才是唯一事实来源

    研究过程全部落盘；模型上下文只保留结论。

  4. 04

    机械门禁取代良好意愿

    证据规则由校验器强制执行，校验不通过，这一轮就直接失败。

  5. 05

    两档，而不是三档

    quick 与 normal，按问题自动选择。没有繁重的编排。

  6. 06

    可核查优先于好看

    每一条论断都可点击追溯；无法核实的一律标注为 unknown。

  7. 07

    证伪是强制动作

    反面证据和相互矛盾的结论必须主动搜寻，绝不能默认它们不存在。

02 为什么还要再做一个

大多数深度研究方案，要么是一套笨重的多智能体框架，要么只是一句单薄的 prompt。这个 skill 走的是中间那条路。

  • 多智能体框架

    拆给很多个智能体

    任务交给许多各司其职的智能体，外面再套一层编排把它们串起来。

  • 单句 prompt

    一句 prompt，没人核对

    一句 prompt 让模型去研究一个话题。快，但交回来的东西没有任何环节会核对。

  • 这个项目 · 中间那条路

    一个 skill，证据落盘

    证据写进磁盘，校验器可以判定这一轮失败，查不到的一律标 unknown，反面证据要主动去找。

它把开源与大厂深度研究里最好的做法收拾到一起 —— 证据契约、来源质量分档、证伪义务、按预算停止、多视角提问 —— 再收进一个自包含的 skill。

03 工作流程

十二个阶段，两道硬门禁。原始检索结果与结构化证据全部落盘，上下文只保留结论。

  1. 1

    规划

    5 个阶段

    先弄清问的是什么、这台主机能做什么，以及这一轮到什么深度。

    1. 01probe探测能力
    2. 02anchor语言 · 格式 · 输出目录
    3. 03clarify1–3 个范围问题
    4. 04tierquick | normal
    5. 05plan具名的研究轴
  2. 2

    研究

    2 个阶段

    检索、打开原文通读，再把证据合并成一份文件。

    1. 06research检索 → 打开 → 评估
    2. 07merge合并为一份 evidence.json
  3. 08Gate ①校验器必须报告 ok
  4. 3

    校验与写作

    3 个阶段

    基于这份证据写报告、渲染引用，最后交付四份产物。

    1. 09write行内引用，不新增事实
    2. 10Gate ②无孤立引用、无未解析引用
    3. 11sources规范化 + 去重
    4. 12deliver4 份产物 + 覆盖与缺口

Gate ① 运行证据校验器：只有它报告 ok，这一轮才会继续。Gate ② 渲染引用，遇到任何孤立引用或未解析引用都会失败。门禁过不去时，这一轮会停下来如实报告，而不是交付一份坏掉的报告。

关键规则

  • 先检索，再打开。搜索结果的摘录永远不算证据。
  • 必须打开原始页面读完之后，才允许写入证据。
  • 主动检索反面证据、失败案例和持不同结论的来源。
  • 核实不了的，就标注为 unknown，绝不猜测。
  • 预算用尽即停止，交付已达成的覆盖，而不是无休止地循环下去。

预算与停止条件

档位 最多抓取 最少不同来源 每轴最多轮次
quick 8 5 3
normal 25 15 3

预算耗尽时，这一轮会停止，交付它已达到的覆盖，并明确列出哪些内容没有覆盖到。

04 交付产物

每一次运行都会把四份产物写进同一个目录。

meld-deepresearch-reports/YYYY-MM-DD-{slug}-{hex4}/

  • report.md

    最终报告，正文带行内编号引用。

  • sources.md

    去重后的来源清单。

  • evidence.json

    结构化的论断、证据、来源与边界。

  • citations.json

    用于渲染报告的引用映射。

报告里的 ## Sources 一节由渲染器生成，不是模型手写的，引用编号也从不手工编排。如果宿主没有文件系统权限，报告会直接以内联方式返回，并说明没有任何内容落盘。
